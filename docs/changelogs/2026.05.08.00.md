# 2026.05.08.00 - Stage-matching material drop boost

Status: Done

## Goal

During a stage, the material type matching that stage should be easier to obtain.
During an upgrade stage, every action type should receive the same material drop
boost.

## Current State

- Complete cycle settlement rolls material once with `MATERIAL_DROP_RATE`.
- The dropped material type is based on the player's current action:
  `gathering`, `building`, `combat`, or `research`.
- Burst runs 3 independent complete settlements, so it rolls material 3 times.
- Partial cycle never rolls material.
- Resource shortage and stage overtime do not affect material drops.
- Current local config sets `MATERIAL_DROP_RATE=0.05`.

## Implementation Gap

The current settlement code reads `MATERIAL_DROP_RATE` directly and rolls:

```python
drop_rate = get_env_float("MATERIAL_DROP_RATE")
if random.random() < drop_rate:
    await player_manager.add_material(db, user_id, action, 1, cycle_end_time)
```

It does not read `stage_state.current_stage_type`, so it cannot boost the rate
for the stage-matching material type.

## Design

Use an effective material drop rate per complete settlement:

```text
base_rate = MATERIAL_DROP_RATE

if current_stage_type == "upgrade":
    effective_rate = min(1.0, base_rate * 2)
elif current_stage_type == action:
    effective_rate = min(1.0, base_rate * 2)
else:
    effective_rate = base_rate
```

The material type granted on success remains the player's action material:

| action | material column |
| :--- | :--- |
| `gathering` | `materials_gathering` |
| `building` | `materials_building` |
| `combat` | `materials_combat` |
| `research` | `materials_research` |

Upgrade stage behavior:

- `current_stage_type = "upgrade"` boosts all four action types.
- A gathering action can drop gathering material at boosted rate.
- A building action can drop building material at boosted rate.
- A combat action can drop combat material at boosted rate.
- A research action can drop research material at boosted rate.

## Scope

### 1. Add effective drop-rate helper

File: `src/core/settlement.py`.

Add a small helper near the material drop code, for example:

```python
def _effective_material_drop_rate(base_rate: float, stage_type: str, action: str) -> float:
    if stage_type == "upgrade" or stage_type == action:
        return min(1.0, base_rate * 2)
    return base_rate
```

Keep the function local to settlement unless another module needs it.

### 2. Read current stage type before material roll

File: `src/core/settlement.py`.

Inside the complete settlement path, read the current stage state before rolling
material. Use the stage type that is current at the material-roll moment.

This matters for Burst: each of the 3 complete settlements is independent. If
the first settlement clears a stage, the next settlement must use the new stage
type when calculating its material drop rate.

### 3. Replace direct `MATERIAL_DROP_RATE` roll

File: `src/core/settlement.py`.

Replace the direct base-rate roll with the effective rate:

```python
base_rate = get_env_float("MATERIAL_DROP_RATE")
stage_info = await stage_manager.get_stage_info(db)
stage_type = stage_info.get("current_stage_type", "")
drop_rate = _effective_material_drop_rate(base_rate, stage_type, action)
if random.random() < drop_rate:
    await player_manager.add_material(db, user_id, action, 1, cycle_end_time)
```

Do not change:

- dropped material type
- dropped amount
- partial cycle behavior
- resource shortage behavior
- stage overtime behavior
- Burst count of 3 rolls
- action output or stage progress formulas

### 4. Add settlement tests

File: `tests/test_engine_settlement.py`.

Add focused tests for:

- normal stage matching action uses doubled rate
- normal stage non-matching action uses base rate
- upgrade stage doubles rate for gathering
- upgrade stage doubles rate for building
- upgrade stage doubles rate for combat
- upgrade stage doubles rate for research
- boosted rate is capped at `1.0`
- partial cycle still never drops material even when boost would apply
- Burst recalculates effective rate for each of the 3 complete settlements

Recommended deterministic approach:

- Set `MATERIAL_DROP_RATE=0.5` when expecting boosted 100% drop.
- Set `MATERIAL_DROP_RATE=0.0` or patch `random.random` when asserting no drop.
- For non-matching action at base rate, set `MATERIAL_DROP_RATE=0.0` or patch
  `random.random` above the base rate.

## Acceptance Criteria

- During `gathering`, `building`, `combat`, and `research` stages, only the
  matching action receives doubled material drop chance.
- During `upgrade` stage, all four actions receive doubled material drop chance.
- Effective material drop rate never exceeds `1.0`.
- Partial cycle continues to grant no materials.
- Burst still performs 3 material rolls and uses the current stage type for each
  roll.
- Resource shortage and stage overtime still do not affect material drop rate.
- No database schema change is required.
